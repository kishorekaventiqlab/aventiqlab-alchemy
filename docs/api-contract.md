# 7. API Contract

> **Status:** v1, stable enough for the AventiqLab platform to build a thin client against.
> Base URL: the stack output `ApiUrl` (`https://{apiId}.execute-api.ap-south-1.amazonaws.com/v1/`).
> TypeScript shapes: `packages/core/src/api-contract.ts` — that file and this document are kept in sync by hand.

## Authentication

`Authorization: Bearer <token>` on every request except `GET /health`.

| Token | Secret | Scope | May call |
|---|---|---|---|
| READ | `alchemy/prod/read-token` | `read` | every `GET` |
| PUBLISH | `alchemy/prod/publish-token` | `publish` | everything |

Tokens are opaque 48-character strings generated by Secrets Manager at deploy. The platform holds the READ
token in **its own** Secrets Manager (same shape as its existing labs-orchestrator token) and sends it from an
Amplify Lambda. The gateway's Lambda authorizer scopes READ tokens to `GET/*`; the service re-checks scope on
every mutation. Authorizer results are cached 5 minutes per token.

Read-scope callers see **immutable** versions only: PUBLISHED, and ARCHIVED when asked for explicitly by
`?version=` (so a learner pinned to a version keeps resolving it after it is retired). Listings, "latest"
and skill lookups never return ARCHIVED. Drafts and review states are publish-scope only.

## Conventions

- JSON in, JSON out, `cache-control: no-store`.
- Slugs (`experienceId`, `skillId`, `artifactId`, `domain`) match `^[a-z0-9]+(?:-[a-z0-9]+)*$`. Versions are `MAJOR.MINOR.PATCH`.
- Errors are always `{ "error": { "code", "message", "details"? } }`:

| HTTP | code | When |
|---|---|---|
| 400 | `bad_request` | malformed body, bad slug/version, wrong method |
| 401 | — (gateway) | missing/unknown token |
| 403 | `forbidden` | read token on a write route |
| 404 | `not_found` | unknown experience/version/skill/artifact, or not visible to this scope |
| 409 | `conflict` | version not greater than latest published; illegal lifecycle transition; concurrent change |
| 409 | `immutable_version` | trying to change or re-publish a PUBLISHED/ARCHIVED version |
| 409 | `artifacts_not_ready` | publish: an upload is missing or its size/sha256 disagrees with the registered digest (`details[]` lists each) |
| 422 | `validation_failed` | manifest/skill/body failed schema or semantic validation (`details[]` = `{path, message}`) |
| 422 | `unknown_skill` | manifest references skills that do not exist (`details[]` = skill ids) |
| 500 | `internal` | |

## Read endpoints

### `GET /health`
`{ ok: true, service: "alchemy", time }`. No auth.

### `GET /experiences?domain=&status=&limit=&cursor=`
```json
{ "items": [ ExperienceSummary ], "nextCursor": "…" | null }
```
`ExperienceSummary = { experienceId, title, summary, domain, category, level, difficulty, tags[], status: DRAFT|PUBLISHED|ARCHIVED, latestVersion, latestPublishedVersion, latestPublishedAt, createdAt, updatedAt }`

### `GET /experiences/{experienceId}?version=`
The self-describing document the platform builds on. Returns the latest published version unless `?version=` names another.
```json
{
  "experience": ExperienceSummary,
  "version": {
    "experienceId": "aws-global-infrastructure", "version": "1.0.0", "status": "PUBLISHED",
    "s3Prefix": "aws/foundation/aws-global-infrastructure/1.0.0/",
    "contentHash": "03f4…2020c",            // sha256 over manifest + artifact digests; stable per version, acts as an ETag
    "createdAt": "…", "updatedAt": "…", "publishedAt": "…", "changelog": "Initial release.",
    "manifest": { …the full manifest: skills, prerequisites, learningObjectives, completion/mastery criteria… },
    "artifacts": [
      { "artifactId": "video-main", "kind": "video", "path": "video/aws-global-infrastructure.mp4",
        "contentType": "video/mp4", "sizeBytes": 45987, "sha256": "…", "title": "…", "durationSeconds": 720,
        "urlPath": "/experiences/aws-global-infrastructure/versions/1.0.0/artifacts/video-main/url" }
    ],
    "statusHistory": [ { "from": null, "to": "DRAFT", "at": "…", "actor": "token:publish" }, … ]
  } | null,
  "links": { "self": "/experiences/{id}", "versions": "/experiences/{id}/versions", "content": "/experiences/{id}/content?version=1.0.0" | null }
}
```

**Detecting a newer version for a pinned learner:** compare `experience.latestPublishedVersion` /
`experience.latestPublishedAt` with the pinned `version` — no manifest diffing needed. `version.contentHash`
identifies the exact bytes a learner was served.

### `GET /experiences/{experienceId}/versions`
`{ experienceId, items: [ VersionSummary ] }` — PUBLISHED and ARCHIVED only for read scope.

### `GET /experiences/{experienceId}/versions/{version}`
`VersionDetail` (the `version` object above).

### `GET /experiences/{experienceId}/content?version=&ttl=`
Everything the learner-facing app needs to render the experience, with a **presigned GET per artifact**.
```json
{ "experienceId", "version", "status", "manifest", "expiresAt",
  "artifacts": [ { …ArtifactRef, "url": "https://aventiqlab-alchemy-content-….s3.ap-south-1.amazonaws.com/…?X-Amz-…", "expiresAt": "…" } ] }
```
`ttl` seconds, clamped to 60–900 (server max is configurable). Videos play straight from S3; nothing is proxied.

### `GET /experiences/{experienceId}/versions/{version}/artifacts/{artifactId}/url?ttl=`
`{ experienceId, version, artifact: SignedArtifact }` — one URL, for lazy loading a single asset.

### `GET /skills?domain=&limit=&cursor=` · `GET /skills/{skillId}`
`{ items: [ Skill & { updatedAt } ], nextCursor }` · `{ skill, updatedAt }`

### `GET /skills/{skillId}/experiences?relation=TAUGHT|ASSESSED|REQUIRED`
`{ skillId, items: [ { experienceId, version, relation, level, versionStatus } ] }` — PUBLISHED only for read scope (never ARCHIVED: nobody should be routed *to* a retired version). This is the query ASTRA will use.

## Publishing endpoints (publish scope)

### `POST /experiences`
Optionally pre-create a catalog shell: `{ experienceId, title, summary, domain, category, level, difficulty, tags? }` → `201 ExperienceResponse`.
Not required — registering a version creates the shell from the manifest. Refused (`409`) once anything is published, because identity fields then come from the manifest.

### `POST /experiences/{experienceId}/versions`
```json
{ "manifest": Manifest,
  "artifacts": [ { "artifactId", "sha256", "sizeBytes" } ],     // one per manifest artifact
  "manifestDigest": { "sha256", "sizeBytes" } }                  // of manifest.json as it will be uploaded
```
→ `201`
```json
{ "experienceId", "version", "status": "DRAFT", "s3Prefix",
  "uploads": [ { "artifactId": "manifest" | "<id>", "key", "method": "PUT", "url", "headers": { "content-type": "…" }, "expiresAt" } ] }
```
Validates the manifest, requires every referenced skill to exist, requires `version` > latest published,
refuses immutable versions. Re-registering a DRAFT replaces it (stale artifact/skill rows are deleted).
Upload URLs live 1 h; the uploader must send exactly the returned headers.

### `POST /publish`
`{ experienceId, version }` → `200`
```json
{ "experienceId", "version", "status": "PUBLISHED", "publishedAt", "s3Prefix", "artifactCount", "totalBytes",
  "verified": [ { "artifactId", "sizeBytes", "sha256Verified": true|false } ], "previousPublishedVersion": "0.9.0" | null }
```
Verifies every object (HEAD size; re-hash if ≤ 32 MB, else size + ETag recorded) before flipping status
atomically. Allowed from DRAFT, SUBMITTED or APPROVED (see [doc 9](./versioning-strategy.md)).

### `POST /experiences/{experienceId}/versions/{version}/status`
`{ status: DRAFT|SUBMITTED|APPROVED|ARCHIVED, note? }` → `200 VersionDetail`. Legal transitions only; `PUBLISHED` must go through `/publish`.

### `PUT /skills/{skillId}`
Body = `Skill` (see [doc 4](./skill-metadata-schema.md)) → `200 { skill, updatedAt }`. Upsert.

## Sequence the platform will use

```
platform Lambda ──GET /experiences?domain=aws──▶ catalog listing
platform Lambda ──GET /experiences/{id}────────▶ metadata, skills, objectives, artifact refs (cacheable)
platform Lambda ──GET /experiences/{id}/content▶ presigned URLs (per learner session, 15 min)
browser ─────────GET presigned URL─────────────▶ S3 (video / reading / assets)
```

## Versioning of this contract

Additive fields are non-breaking. Removing or renaming a field, or changing an enum, is a contract change
that goes through a PR pinging platform, ASTRA and Alchemy. The path prefix `/v1` is the API Gateway stage;
a breaking change would deploy a `/v2` stage alongside.
